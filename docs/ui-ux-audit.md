## 1. 構造的な問題

### S1. 再生位置の「時計」が分散している 🔴

**現状**

- `useInterpolatedPosition` は呼ぶたびに独自の rAF ループを持つ。Now Playing を開くと同時に動くループ:
  - `NowPlayingLight`（補間 1 + `useLoudnessLevel` の `useAnimationFrame` 1）
  - `RecordDisc`（spring 用と raw 用で 2）
  - `WaveformSeek` 1、`LyricsPanel` 1、ドックの `PlayProgressRing` 1
  - 下に mount されたままのアルバム詳細の `SegmentFill` 1
- それぞれのホストが `usePlaybackPosition()` を購読しているため、250ms ごとに `LyricsPanel`（全行の `m.div`）、`RecordDisc`（`DiscLabel` 含む）、`NowPlayingLight`、`PlaybackWaveformBand`（×2 本）、`NextTrackPreview` が再レンダーされる。
  - `LyricsPanel` が位置を購読している理由は `useLyricsSync` と補間の入力だけ（`lyrics-panel.tsx:37,46,48`）。
- `useLoudnessLevel`（`use-loudness-level.ts:19`）は一時停止中も、Artwork backdrop が off で Light が描かれないときも、毎フレーム回り続ける。
- 「シーク（位置の不連続）」の検出が 3 か所にある。
  - `useInterpolatedPosition`（spring に切り替える）
  - `useJumpSpin`（`playback-waveform-band.tsx:26`、数字を余分に回す）
  - `RecordDisc` の effect（`record-disc.tsx:149-162`、ディスクを 1 回転させる）
  - どれも「前回の位置 + 経過時間」から推定しているが、基準時刻の取り方が少しずつ違う。レポートの遅延（IPC の揺れ）で誤検出したときに、3 つの演出がばらばらに反応しうる。

**提案: `entities/playback` に単一の再生クロックを置く**

```text
entities/playback/model/playback-clock.ts
  clock.position   MotionValue<number>  補間済みの位置。rAF は 1 本だけで、再生中かつ購読者がいるときだけ回る
  clock.jump       { from, to, kind: "seek" | "track" | "resume" } | null   不連続を 1 か所で判定して配る
  clock.loudness   MotionValue<number>  S2 のエネルギー曲線から導出。Light が有効なときだけ計算
```

- 不連続の判定は推定ではなく**事実**から行う。controller は `seek()` を呼んだこと、`item` が変わったことを知っているので、`acceptPlayback` の中で `jump` を確定できる。backend のスナップショットに `seekRevision` を足せば、外部要因のシーク（将来の SMTC など）も同じ経路に乗る。
- 位置を描く部品は React の state を購読せず、`clock.position` を `useTransform` で束ねるだけにする。250ms の再レンダーが消える。
- `LyricsPanel` は `currentIndex` だけを購読する（行が変わったときだけ再レンダー）。
- architecture.md の「位置は `usePlaybackPosition` だけ」の方針を「位置は `playbackClock` だけ。`usePlaybackPosition` は数字を表示する部品（時刻ラベル）専用」に更新する。

### S2. 波形データの読み方が演出ごとに違う 🔴

| 演出                   | 使うデータ | スケール                   | 箇所                   |
| ---------------------- | ---------- | -------------------------- | ---------------------- |
| Now Playing の波形バー | RMS        | dB（-36dB を床）           | `waveform-model.ts:25` |
| レコード盤の溝の幅     | peak       | 線形（`peak / 255`）       | `groove-model.ts:26`   |
| 溝の途切れ（無音判定） | peak       | 線形の閾値 `10`            | `groove-model.ts:13`   |
| Light の呼吸           | peak       | 線形、1 バケットをそのまま | `loudness.ts:2`        |

- 直近のコミットで波形バーは「peak は音量感を表さない」という理由で RMS + dB に直されたが、同じ理由がディスクと Light にもそのまま当てはまる。
- 現代的なマスタリングの曲は peak がほぼ常に上限近くに張り付く（推定）。そのため、溝の幅はほぼ一定になり、Light の呼吸はほとんど揺れない。演出の意図（「曲の形が見える」「音量で呼吸する」）が出にくい。
- 提案: `entities/playback` に `trackEnergy(waveform) -> { level: Float32Array /* 0-1, dB スケール */, silentBelow }` を 1 つ置き、トラックごとに 1 回だけ計算してメモ化する。3 つの演出は全部これを読む。スケールの変更が 1 か所で済み、テストも 1 つで済む。

### S3. 歌詞⇄波形リンクの Context 🟠

- `LyricsWaveformLinkProvider`（`lyrics-waveform-link.tsx:29`）は `activeSpan`（行が変わるたび）と `hoveredWaveformMs`（ポインタ移動ごと）を 1 つの value に入れている。
- 波形の上でポインタを動かすと、`LyricsPanel`（全行）、`RecordDisc`、両方の `PlaybackWaveformBand` が毎回再レンダーされる。
- さらに `RecordDisc` は `activeSpan` が変わるたびに溝全体（1 万点超のパス）を計算し直し、ベースのキャンバスを描き直す（`record-disc.tsx:97-111`）。
- 提案:
  - zustand の小さなストアにしてセレクターで読む（playback と同じ流儀）。
  - ディスクは「光っている行の溝」だけを別キャンバスにし、ベースの溝は波形が届いたときに 1 回だけ描く。

### S4. 「文字を CSS `content` で描く」方式 🟠

`RollingNumber`、`FlapText`、`KineticText` は、見えている文字を `before:content-[attr(data-glyph)]` で描き、実際のテキストは `sr-only` に置いている（`rolling-number.tsx:22`、`kinetic-text.tsx:45-52`）。

- スクリーンリーダー向けには問題ないが、次の点が壊れる。
  - **選択・コピー・ページ内検索ができない。** Now Playing の曲名は、初回表示ではテキストなのに、曲送りの後は（Now Playing を開き直すまで）選択できなくなる。挙動が一貫しない。
  - **1 文字ごとの `inline-block`** で、カーニングや合字が効かず、日本語の禁則処理（行頭の「、」「ー」など）も効かない。`UNBREAKABLE_MAX` の単語判定は空白区切りの言語向けで、日本語の曲名には効かない。
- 歌詞の `LineFill` は正しい設計になっている。実テキストを通常のフローに置き、装飾は `aria-hidden` の重ね描きにしている。
- 提案: **「本物のテキストは常にフロー上にあり、動きは aria-hidden のオーバーレイだけ」**を共通ルールにする（DESIGN.md の原則 10 として追加済み）。
  - KineticText は、実テキストを `opacity:0` から戻す間だけ、上にオーバーレイを重ねて、アニメーション後に外す。
  - RollingNumber は数字だけなので現状のままでも実害は小さい。ただしルールとしては揃える。

### S5. 再生中アイテムの情報不足 🟠

- `DiscSlot` は track number を得るためだけに、再生中アルバムの `useAlbumTracks` を引いている（`now-playing-content.tsx:170-174`）。
  - アルバムが変わるたびに 1 ページ（100 件）の取得が走る。
  - 100 曲を超えるアルバム（ボックスセットなど）では、2 ページ目以降の曲の番号が出ない。
  - アルバムキーを `albumArtist ?? artist` から組み立てていて、カタログ側のキーと一致しない可能性もある。
- 提案: `PlaybackItem` に Now Playing の fact 行とリンクに要るものを持たせる。backend の `PlaybackItem` はすでにライブラリから組み立てているので、足すだけで済む。
- **L1（Now Playing の作り直し）の前提。** レコード盤を削除しても、fact 行（`2019  Track 4 of 11`）とアルバム・アーティストへのリンクのために必要。

**変更点（経路は `library/playback.rs` → `app/playback_context.rs` → `audio/playback/item.rs` → bindings）**

| 追加するフィールド                   | 取得元                                                                      | 使う場所                                                    |
| ------------------------------------ | --------------------------------------------------------------------------- | ----------------------------------------------------------- |
| `track_number: Option<u32>`          | `PlayableTrack` を作る SQL に列を足す                                       | fact 行 `Track 4`                                           |
| `disc_number: Option<u32>`           | 同上                                                                        | fact 行 `Disc 2 · Track 4`（ディスクが 2 枚以上のときだけ） |
| `album_track_count: Option<u32>`     | 同上。アルバム内の件数を `COUNT(*) OVER (PARTITION BY アルバムキー)` で出す | fact 行 `of 11`                                             |
| `year: Option<i32>`                  | 同上（日付があれば年）                                                      | fact 行                                                     |
| `album_key: Option<LibraryAlbumKey>` | カタログと同じ規則で組み立てたキー                                          | Now Playing / ドック / キューからアルバムへのリンク         |

- フォーマット（`FLAC 24/96`）は `PlaybackItem` に入れない。実際にデコードしている値は `usePlaybackSignalPath().source` にすでにあるので、それを使う（ライブラリの値とデコード結果が食い違ったときに、実際の値の方を出すため）。
- アルバムへのリンクは、renderer で `albumArtist ?? artist` からキーを推測するのをやめ、`album_key` を使う。ドックの Sleeve の右クリックメニュー（`dock-identity.tsx:105-106`）にも同じ推測があるので、同時に置き換える。
- `PlaybackItemSeed::from_file`（ライブラリ外のファイル）では全部 `None`。fact 行は、ある項目だけを出す。
- キューの項目（`PlaybackQueueItem`）にも同じ値が流れる。U2 でキューの IPC をウィンドウ化するときに、サイズの増加を一緒に見る。
- テスト: `playback_context` の統合テストに「アルバム再生で `track_number` と `album_track_count` が入る」「Tracks 再生でもアルバムの件数が入る」を足す。bindings の再生成（`pnpm bindings`）と、e2e モック（`tests/fixtures/native-api.ts`）の更新も必要。

### S6. render 中に ref を書き換えている 🟡

- `NowPlayingContent` の `showLyricsRef` と `openedOn`（`now-playing-content.tsx:40-46`）は render 中に ref を読み書きしている。以前 `directionRef` で指摘されたのと同じ型の問題で、StrictMode や concurrent rendering で結果がずれうる。
- `showLyrics` は「直前のトラックで歌詞があったか」を state として持つべき値。`useTrackLyrics` の `placeholderData: keepPreviousData` で同じことが宣言的に書ける。

### S7. DOM を走査して機能をつなぐ実装 🟡

- `ScrollIndex` は `document.elementFromPoint(左端 + 64px, …)` で `li[data-index]` を探す（`library-workspace.tsx:176-177`）。
- `RovingLight` は `closest("li[data-index]")` で探し、ソートのスライドは `useInView` をタイルごとに持つ（`media-grid.tsx:94`、IntersectionObserver がタイル数だけできる）。
- 3 つの演出が、それぞれマークアップの形に依存している。U1 でグリッドを仮想化すると全部作り直しになる。
- 提案: U1 の仮想化グリッドに「見えている範囲（`virtualizer.range`）」と「各アイテムの矩形」を出させ、3 つの演出はそれを入力にする。DOM クエリがなくなる。

### S8. 演出の有効範囲を決めるスイッチが reduced-motion しかない 🟡

- 演出を増やす方向の開発が続くなら、「どの演出が、どの設定で、どこまで動くか」を 1 か所で持つ方がよい。
- 提案: `shared/ui/motion` に `useMotionBudget()` を置き、`full | calm | reduced` を返す（`calm` は U5 の「注意の予算」に沿って、常時動く演出だけを止める）。Settings に `Motion: Full / Calm` を追加するかどうかは任意。最低でも、ロジックの入口を 1 つにしておく。

## 2. インタラクションと動線

### 2.1 ライブラリ

- **U1 `Load more` ボタン** 🔴（`library-workspace.tsx:132-137`、backend `PAGE_SIZE = 100`）
  - Tracks は仮想化されているのに、100 行ごとにクリックが必要。1 万曲なら 100 回押すことになる。
  - Albums と Album Artists は非仮想化で、ページを足すほど DOM が増える（1 タイルあたり `m.li` + `useInView` + 画像）。
  - `ScrollIndex` は読み込み済みの範囲しか知らないので、スクロールバーを掴んで下へ飛ばしても文字が追従しない。
  - 提案:
    - 末尾の番兵（または `virtualizer.range` の末尾）で自動的に次のページを取る。
    - グリッドも行単位で仮想化する（列数はコンテナ幅から計算できる。`grid-cols-[repeat(auto-fill,12rem)]` を固定幅の計算に置き換える）。
    - 将来はキーセットページング（improvement-report A6 の後半）で深いページを O(1) にする。
- **ソートのスライドとスクロールのリセットが衝突する** 🟠
  - ソートで `stateKey` が変わると `useScrollTopOnChange` が先頭に戻す。そのため、「見えていたタイルが新しい場所へ滑る」前に、見えている範囲自体が入れ替わる。
  - スクロールコンテナに `layoutScroll` がなく、motion の layout 計測はコンテナ内のスクロール量を考慮しない。スクロールした状態では、タイルが誤った位置から飛んでくる可能性が高い（要確認）。タイル → 詳細画面の共有要素遷移も同じ条件にある。
  - 提案: `WorkspaceScroll` のビューポートに `layoutScroll` を付ける。ソート時は「先頭へ戻す」か「滑らせる」かのどちらかに決める。おすすめは「スクロールしていないときだけ滑らせ、スクロールしていれば先頭へ戻して crossfade」。
- **空のライブラリから先に進めない** 🟠
  - 初回起動時は `No albums in your library.` だけが表示され、Settings への導線がない。
  - `EmptyStatus` に `Add a music folder`（Settings に移動してフォルダ選択を開く）を置く。
  - フォルダを追加した直後にスキャンを自動で始めるかどうかも決めておく（今は `Rescan` を押す必要があるように見える。backend 側の挙動は要確認）。
- **Tracks にだけスクロールインデックスがない**。`indexFor` はグリッド専用（`li[data-index]` 依存）。S7 を直せばテーブルにも同じものを出せる。
- **フィルタの入力欄にキーボードで行く手段がない**。`Ctrl+F` か `/` でフォーカスする。

### 2.2 トラックの再生とキュー

- **U4 行クリックがキューを黙って置き換える** 🟠
  - Tracks で 1 クリックすると、それまでのキュー（手で並べ替えた順も含む）が全件消える。確認も Undo もない。DESIGN の「確認ではなく Undo を優先する」に沿うなら、置き換え直後に `Queue replaced · Undo` を出す。
  - 右クリックメニューがない。最低限 `Play next`、`Add to queue`、`Go to album`、`Go to artist`、`Show in Explorer`、`Properties`。backend にも Play next / Append の IPC がない（`bindings.rs` のキュー系は get / remove / move / clear のみ）。
- **キューからその曲へジャンプできない** 🟠
  - キューの行はクリックしても何も起きない。多くのプレイヤーで最も使われる操作のひとつ。`play_queue_item(id)` を追加する。
- **キューに履歴がない**
  - DESIGN には「queue history は Ink-3」とあるが、実装は現在の曲と upcoming だけ。前に戻る動線が Previous ボタンだけになっている。
- **ドラッグの見え方** 🟡（`queue-panel.tsx:68-92`、`use-queue-drag.ts`）
  - 掴んだ行はポインタに追従せず、その場で傾くだけ。挿入位置に隙間が開く方式なので、「持っている物」と「置く場所」が離れて見える。
  - リストの端に近づいても自動スクロールしないので、長いキューでは見えている範囲の外へ動かせない。
  - 提案: 掴んだ行は `y` をポインタに 1:1 で追従させ（DESIGN の「直接操作は 1:1」）、元の位置は詰める。端では自動スクロールする。
- **`Clear upcoming` が即時実行で Undo がない**。U4 と同じ Undo の仕組みに乗せる。
- **U2 キューの規模** 🔴
  - Tracks から再生するとライブラリ全体がキューに入る。キューパネルは全件を `m.li layout="position"` で描き、キューが変わるたびに backend から全件の JSON が届く（`snapshot.rs:221`）。
  - 数千件で、パネルを開いたとき・曲が進むたびに重くなる（要計測だが、構造的に線形）。
  - 提案:
    - パネルを仮想化し、`layout` アニメーションは見えている行だけにする。
    - IPC は `{ revision, current, upcomingCount, window: [offset, items] }` のようなウィンドウ化を検討する（ドックの次曲プレビューが必要なのは先頭 1 件だけ）。

### 2.3 シークと音量

- **U3 拡大鏡がシークの精度を上げない** 🔴
  - `fisheye` はバーを横に太らせるだけ（`waveform-bars.tsx:58-74`）。位置の計算は `positionFromOffset` の線形のまま（`use-pointer-seek.ts:38-41`）。
  - 太ったバー同士は重なるだけで、間隔は広がらない。つまり「細かくシークできる」ように見えるが、実際には何も変わらない。DESIGN の「装置の真似をしない（実データの変化だけを動かす）」にも反する。
  - 選択肢:
    1. 本物の拡大にする。ドラッグ中はポインタの近傍で時間の軸を伸ばし（fisheye の逆写像で位置を計算）、バーの位置も同じ写像で動かす。
    2. 一般的な方法にする。ドラッグ中にポインタを縦に離すほど移動量が小さくなる（iOS のスクラブ速度）か、`Shift` で 1/10 にする。
    3. 削除する。
  - どれを選ぶにしても、見た目と挙動は一致させる。
- **矢印キーのシークが連打で落ちる**。`seek()` は `seekPending` の間の要求を捨てる（`playback-session.ts:230`）。長押し（`event.repeat`）では数回に 1 回しか効かない。音量と同じく「最新の要求だけを送る」合流方式にする。
- **音量スライダーが線形振幅** 🟠（`dock-volume.tsx:142-151`）
  - 表示と wheel は dB なのに、スライダーは 0〜1 の振幅。右半分が 0〜-6dB、実用域の -40〜-10dB は左 3 割に詰まる。
  - スライダーも dB（たとえば -60〜0dB + 左端で無音）にする。表示・wheel・ドラッグが同じ軸になる。

### 2.4 Now Playing とドック

- **Now Playing から移動できない**
  - Now Playing の中で、アーティスト名とアルバム名はただのテキスト。「アルバムへ移動」はドックの Sleeve の右クリックメニューにしかなく、Now Playing を開いている間は Sleeve が閉じるボタンに置き換わるので、そこにも辿り着けない。
  - Now Playing とドックのアーティスト名・アルバム名をリンクにする（リンクで移動すると Now Playing は閉じる。現在の history state の設計どおり）。
- **Escape で閉じない**。Back とボタンだけ。レイヤーなので Escape で閉じるのが自然。
- **`Ctrl+L` が再生していなくても開く**。ドックのボタンは disabled になるのに、ショートカットは `Nothing playing` の画面を開く（`use-playback-shortcuts.ts:41`）。
- **トグルの状態がわからない**。ドックの `Lyrics`（実際は Now Playing の開閉）と `Queue` に `aria-pressed` も見た目の状態もない。Shuffle / Repeat と同じ「点」を付ける。`Lyrics` というラベルも、実際の役割（Now Playing）とずれている。
- **歌詞の読み込み中にレイアウトが 2 段階で変わる**。`showLyricsRef` の初期値が `true` なので、歌詞のない曲で初めて開くと、2 カラムで開いた直後に中央寄せへ切り替わる。Sleeve が移動している途中で目標の位置が変わる。
- **次曲プレビュー**（`next-track-preview.tsx`）: 一時停止中も残り 3 秒なら出続ける。リピート All の末尾では、次に鳴る曲（先頭）があるのに出ない。

### 2.5 アルバム詳細

- **Strip の各区間がタブ移動の対象になり、クリック範囲が 4px しかない**（`album-strip.tsx:42-56`）。20 曲のアルバムでは、表に着くまでに 20 回 Tab を押す。表と機能が重複しているので、Strip は `tabIndex={-1}` にしてポインタ専用にする。当たり判定は上下に広げる（見た目は 4px のまま、`::before` で 16px）。
- **`Play album` が常に `Play album`**。このアルバムが再生中でも一時停止にならず、状態も出ない。DESIGN の「再生のアフォーダンスは 1 種類（丸い再生ボタン）」とも違う。`Shuffle` もない（DESIGN には記載あり）。
- **マルチディスクの区切りがない**。requirements にある disc number も表示されない。
- **トラックの詳細（ジャンル、日付、チャンネル数、ファイルパス）を見る場所がない**。requirements の Metadata に列挙されているのに、UI のどこにも出ない。U4 のメニューに `Properties` を置き、Sheet で見せる。

### 2.6 設定

- **スキャンの進捗が 2 か所に出る**。見出し横の `Scanning 1,234 inspected`（`aria-live="polite"`）と、下の 4 つのカウンター。前者は件数が変わるたびに読み上げられ、スクリーンリーダーがうるさくなる。live region には状態の変化（開始・完了・失敗）だけを入れる。
- **進捗バーがずっと不定**。`discoveredCount` があるなら、`inspected / discovered` で確定値にできる（discover 中だけ不定）。
- DESIGN の「Settings は Gutter に揃った台帳」は、まだ shadcn の `Item` のリストのまま。

### 2.7 キーボード

| 不足                           | 提案                                                      |
| ------------------------------ | --------------------------------------------------------- |
| Now Playing を Escape で閉じる | 追加                                                      |
| 検索へのフォーカス             | `Ctrl+F` または `/`                                       |
| 音量                           | `Ctrl+↑/↓`（±1dB、wheel と同じ刻み）                      |
| シャッフル・リピート           | `Ctrl+S` / `Ctrl+R`（WebView の既定と衝突しないか要確認） |

グローバルな `←/→` のシークは、グリッドに矢印キー移動を入れると衝突する。「フォーカスがコレクションの中にあるときは、矢印キーをコレクションに渡す」ルールを `usePlaybackShortcuts` に入れる。

## 3. レイアウト（UX から見た配置）

### L1. Now Playing のレイアウト（レコード盤の削除を前提に作り直す） 🟠

**現状の問題**

- 左カラムは幅が固定（`md:w-[28rem]`）で、Sleeve も固定サイズ（18rem / 22rem）。ウィンドウの形に関係なく同じ寸法になる。
- 高さ方向に対応していない。高さ 720px のウィンドウでは Now Playing に使えるのは 576px（720 − 40 − 104）。Sleeve 288px + 最大 3 行の `text-4xl` の曲名 + 余白で、曲名が長いと下の波形の帯に重なる。
- 歌詞がないときは、すべてを縦に積んで中央に置く。デスクトップのウィンドウは横長なので、足りない縦を使い、余っている横を空けている。
- 次に何が鳴るか、どのアルバムの何曲目か、どんなフォーマットか（Path）が Now Playing の中にない。
- 歌詞の有無が確定する前に 2 カラムで開き、確定後に中央へ切り替わることがある（§2.4）。

**前提**: S5 の `PlaybackItem` 拡張（`track_number` / `disc_number` / `album_track_count` / `year` / `album_key`）を先に入れる。fact 行とリンクはこれがないと作れない。

**方針**

1. **サイズは画面の形から決める。** Sleeve の一辺は `min(使える高さ − 情報ブロック, カラム幅)`。Now Playing の section を `container-type: size` にし、`cqh` / `cqw` で計算する。固定の rem はやめる。
2. **中身は 3 種類だけ**: 見るもの（Sleeve）、読むもの（歌詞）、操作するもの（波形）。情報ブロックはその脇に置く。
3. **狭くなったら並べ替え、次に二次情報を落とす。** 文字は最後まで縮めない（DESIGN の Accessibility）。
4. **縦のアラインメントを揃える。** Sleeve の左端、波形の左端、ドックの閉じるボタン（Sleeve の戻り先）の左端を同じ線に揃える。Sleeve は開閉のとき、この線に沿って上下に移動する。

## 5. 遊び心の演出の評価（U5）

直近のコミットで、演出は次のように増えた。個々の出来は良く、データに根拠があるという DESIGN の原則にも概ね沿っている。問題は**同時に動く量**。

Now Playing で曲が流れているとき、何もしなくても動き続けるもの:

1. Light の呼吸（opacity + scale）
2. レコード盤の回転
3. 歌詞の 1 文字ずつの点灯 + 2px の浮き上がり
4. 歌詞のスクロール
5. 波形の再生済み部分
6. 経過時間と残り時間の数字の回転（毎秒）
7. ドックの再生リング

周辺視野で常に 5 つ以上が別々のリズムで動いており、DESIGN の「自分から動くのはこれだけ」リストも、演出を足すたびに伸びている。

**提案: 「注意の予算」を DESIGN.md に明文化する**（原則 7 として追加済み。以下はそれに沿った演出ごとの判断）

- 常に動いてよいのは「現在位置を表すもの」1 系統だけ。Now Playing では歌詞（あれば）、なければ波形とディスク。
- それ以外は「変化したときにだけ動く」。
  - 数字は、シークのときと曲が変わるときだけ回す。1 秒ごとの進みは静的に書き換える。
  - Light の呼吸は振幅を下げるか、S2 のエネルギー曲線で「サビで明るくなる」程度のゆっくりした変化にする（80ms / 400ms の追従ではなく、数秒の窓で平均する）。
- 個別の判断:

| 演出                        | 判断           | 理由                                                                    |
| --------------------------- | -------------- | ----------------------------------------------------------------------- |
| レコード盤                  | 残す           | 「曲の形の地図」として成立している。S2 の RMS dB 化で本来の見え方になる |
| 歌詞の文字ごとの点灯        | 残す           | このアプリの見せ場                                                      |
| 文字の 2px の浮き上がり     | 弱める         | 点灯と二重になっている。`calm` では切る                                 |
| Light の呼吸                | 調整           | 上記のとおり                                                            |
| 数字の毎秒の回転            | 調整           | P10                                                                     |
| シークの拡大鏡              | 作り直すか削除 | U3                                                                      |
| スクロールインデックス      | 残す           | 仮想化（S7）と合わせて、読み込み範囲の外でも正しく出るようにする        |
| 曲名の 1 文字ずつのスライド | 作り直す       | S4（選択できない、日本語の改行）                                        |
| キューのシャッフル時の段差  | 残す           | 1 回きりで、意味がある                                                  |
| 次曲プレビュー              | 残す           | 小さく、意味がある                                                      |

## 7. テスト

- 直近の演出（レコード盤、スクロールインデックス、ローミングの光、次曲プレビュー、拡大鏡、KineticText）は、e2e で 1 件も触れられていない。純関数のテスト（groove、loudness、sort-index、fisheye）はある。
- 追加するなら、見た目ではなく**不変条件**を確認する（`motion.e2e.ts` の方針どおり）。
  - Now Playing の曲名は、曲送りの後もテキストとして選択できる（S4）
  - 波形上でポインタを動かしても、`LyricsPanel` の再レンダー回数が増えない（S3。React Profiler か描画回数のカウンター）
  - 1,000 件のキューでパネルを開いても、描画される行数は画面内の分だけ（U2）
  - スクロールした位置でソートしても、スクロール位置とタイルの位置が一貫している（§2.1）
- S1 の単一クロックは、`playback-clock` を純関数（アンカー → 推定、事実ベースの jump 判定）と薄い hook に分け、vitest で「seek を呼ぶ → jump が 1 回だけ出る」「IPC が遅れても jump が出ない」を確認する。

## 9. 実装状況（2026-09-29）

**実装済み**

- レコード盤の削除（`record-disc/`、`labelInk`、`DiscSlot`）
- S1: 単一の再生クロック（`entities/playback` の `playbackClock` / `usePlaybackClock`）。rAF は 1 本で、クロックを保持する部品があり再生中のときだけ回る。シークは backend の `ActiveSession.seekRevision`（完了したシークの数）から**事実として**検出し、`usePlaybackJump` で 1 回だけ配る（IPC の遅れではジャンプしない）。進捗の塗り・リング・歌詞行・Strip・Light は再レンダーなしでクロックを読む。歌詞の同期（`useLyricsSync`）は行が変わったときだけ再レンダー。旧 `useInterpolatedPosition` と 3 か所のシーク検出は撤去。純関数（`playback-clock-model`）とクロック本体のテストあり
- S2: `trackEnergy`（RMS の dB スケール、波形ごとに 1 回だけ計算）を Light の呼吸が読む。波形バーと同じスケール。呼吸は opacity のみ（P2）、追従は数秒の窓（U5）、フレームループなし（P3。クロックの `position` の変化で進み、一時停止では自然に止まる）
- S3: 歌詞⇄波形リンクを zustand ストア（セレクター購読）に。歌詞の行は `memo`（P5）。波形バーも `memo`（P6）
- S4: `KineticText` は実テキストを常にフローに置き、動きは `aria-hidden` のオーバーレイ。`RollingNumber` / `FlapText` は数字と装飾の文字だけなので、現状の方式（実テキストは `sr-only`）のままとした
- S5: `PlaybackItem` に `trackNumber` / `discNumber` / `year` / `albumKey` / `albumTrackCount`。アルバム件数は 1 回のグループ化クエリで出す（Tracks 再生ではライブラリ全体を 1 回、単曲では該当アルバムだけ）。アルバムへのリンクはカタログと同じキー（`albumKey`）を使う
- S6: レイアウトの状態を ref ではなく state に。歌詞の先読み（現在の曲と次の曲）
- S7: DOM 走査の撤去。スクロールインデックスはリストが報告する先頭の項目（仮想化の範囲）から、ローミングの光はタイルが自分の index と要素を報告して動く
- S8: `useMotionBudget()`（`full | calm | reduced`）と Settings の `Calm motion`（backend の `appearance.calmMotion`）。`calm` では Light の呼吸と歌詞の文字の浮き上がりが止まる
- U1: `Load more` を自動ページングに（番兵、800px 手前で取得）。P7（`gcTime`）。Albums / Album Artists の行単位の仮想化（P9 の `useInView` も撤去）。`layoutScroll`。ソートは、スクロールしていなければタイルが滑り、スクロールしていれば先頭へ戻してフェードイン。Tracks にもスクロールインデックス。仮想化のグリッドは `overflow-anchor: none`（ブラウザのスクロール固定がタイルの入れ替わりと喧嘩する）
- U2: キューの仮想化（固定行高、ドラッグは算術で位置決め、端で自動スクロール）。IPC のウィンドウ化（スナップショットは現在の曲・直近 50 件の再生済み・先頭 200 件の予定と `upcomingCount`。残りは `get_playback_queue_window` を 100 件ずつ、表示範囲の周りだけ読む）。キューの履歴（Ink-3、クリックでその曲へ戻る）
- U3: 拡大鏡を削除し、ドラッグの分解能を実際に変える方式に（バーから離れるほど遅く、Shift で 1/10）
- U4: キュー項目のクリックでジャンプ（`play_queue_item`、再生済みも可）、`Play next` / `Add to queue`（`enqueue_track`）、`Go to album` / `Go to artist` / `Show in Explorer` / `Properties`（タグ・フォーマット・パスのシート）、`Clear upcoming` の Undo（200 曲まで）、`Queue replaced · Undo`（200 曲までは並びごと正確に、それより長いキューは開始元の context から。再生位置も戻す）
- U5: 注意の予算を DESIGN.md に明文化（原則 7）。`calm` で常時動く演出を止められる
- L1: Now Playing の作り直し（高さ連動の Sleeve、歌詞なしは横並び、Up next、fact 行 `2019  Track 4 of 11`、アーティスト・アルバムのリンク、歌詞なしの 1 行ヒントとパス）
- §2.1: `/` と `Ctrl+F` でフィルタ、空のライブラリから設定への導線、グリッドの矢印キー移動（フォーカスがグリッドの中にあるときの矢印はグリッドのもので、シークしない）
- §2.3: 矢印キーのシークの合流、音量スライダーの dB 化、`Ctrl+↑/↓` で音量、`Ctrl+S` / `Ctrl+R` でシャッフル・リピート
- §2.4: Escape で閉じる、`Ctrl+L` は再生中のみ、ドックのトグルの `aria-pressed`（ラベルは `Now Playing`）、次曲プレビューは再生中のみ
- §2.5: Strip をタブ順から外し当たり判定を拡大、アルバムの `Play` は再生状態を反映、`Shuffle`、ディスクの区切り、タイルのホバー再生ボタン
- §2.6: スキャン件数を live region から外した。再スキャンの進捗バーは確定値（前回のスキャンが残したファイル数に対する発見数。初回は不定のまま。backend の `expectedCount`）
- P10: 経過時間の毎秒の回転をやめ、シークのときだけ回す
- §6: 文字化けの修正

**見送り（理由つき）**

- ライブラリ一覧のランダムアクセス（スクロールバーを掴んで深い位置へ飛んでも、まだ読み込んでいない範囲は順に取得される）。カタログの cursor は順番に辿る形なので、offset で読む API（キーセットページング。improvement-report A6）とまとめて行う
- Settings の台帳化: 現状の `Item` のリストで足りる（§6 の判断のとおり）
- L2 のドック右側の整理: 1024px で見て詰まっていなかったので、`Now Playing` のボタンは残した
- ドックの `Now Playing` ボタンと、Now Playing 内の Tab 順の間引き（roving tabindex）: 矢印キー移動を入れたので、Tab 順を減らす必要は出ていない
