# UI 改善点レビュー

対象: 既存コードの通読と、Playwright（モックデータ）で撮影した各画面のスクリーンショット。
DESIGN.md などの既存ルールには縛られず、自由に評価した。

問題はアニメーションが一番多い。「ダサく見える」主因は、演出の趣味より**仕組みの不具合**にある。

---

## 1. アニメーション（最優先）

### 1.1 見た目を壊している不具合

1. **Now Playing のジャケットが、ドックから移動してくる途中で切り取られる**（`now-playing-layer.tsx:25`）
   - 移動先のジャケットは、`overflow-hidden` と `clip-path` が掛かった section の中にある。
   - ドックはこの section の外にあるため、移動の出発点が見えない位置になる。
   - 結果として「ジャケットが飛んでくる」ではなく、「下から幕が開いて、途中からジャケットが湧いて出る」ように見える。
   - 開き方自体も clip-path によるワイプで、PowerPoint の画面切り替えのような印象になる。

2. **タイトルが移動中に伸び縮みして歪む**（`dock-identity.tsx:76` → `now-playing-content.tsx:41`）
   - `text-sm` から `text-lg` へ、幅も truncate も違う要素同士を `layoutId` でつないでいる。
   - motion は transform の scale で補間するため、移動中の文字が横に引き伸ばされ、ぼやける。
   - 文字は共有要素にせず、クロスフェードにした方がきれい。

3. **ドックの中身が縦に潰れる**（`playback-region.tsx:28`、`playback-dock.tsx:46`）
   - 高さ（`h-26`→`h-22`、`h-3`→`h-0`）を `layout` アニメーションで変えている。
   - これは scaleY による補間で、子要素には `layout` が付いていない。
   - そのため、開閉のたびに再生ボタン群やアートワークの光が一瞬縦に潰れる。

4. **プログレスがカクつき、再生位置の線とずれる**（`waveform-seek.tsx:568`、`:736`）
   - 250ms ごとに届く再生位置に対して、0.2 秒のスプリングを毎回かけ直している。
   - その結果「動く→止まる→動く」の階段状の動きになる。
   - 塗りつぶしはスプリングで動くが、再生位置の縦線（`left:%`）はアニメーションせず即座に跳ぶ。この 2 つが常にずれている。
   - 対策: 歌詞の同期と同じく、「最後に届いた位置から時間を補間して、rAF で線形に進める」。スプリングはシーク時のジャンプだけに使う。

5. **曲送りが遅く、動きが揃っていない**（`dock-identity.tsx:61`、`:158`）
   - `AnimatePresence mode="wait"` のため、前の曲が退場しきってから次の曲が入る。約 0.6 秒、何も表示されない瞬間がある。
   - ジャケットは 24px、タイトルは 16px ずれて動くが、アーティスト名はアニメーションせず即座に切り替わる。3 つがばらばらに動く。

### 1.2 場当たり的な演出

- Now Playing の中で `delay: 0.12 / 0.18`、`duration: 0.18 / 0.2`、`y: 8` が直書きされている（`now-playing-content.tsx:49-70`）。モーションのトークンを定義しているのに使われていない。
- 歌詞パネルが曲送りのたびに丸ごとフェード＋下から上へスライドして出てくる。典型的な「AI 生成っぽい」入場演出。
- Sheet・Tooltip・Select は shadcn のデフォルト（`zoom-in-95` + `slide-in-from-2`）のままで、アプリ固有の動きになっていない。Tooltip が白背景に反転していて、暗い UI の中で目に刺さる。
- ライブラリから詳細画面への共有要素遷移は、DESIGN.md には書かれているが**実装されていない**（ただ画面が切り替わるだけ）。
- タイルのホバーは `opacity-80` で暗くなるだけで、無効化された要素のように見える。
- 再生／一時停止のアイコンが即座に切り替わり、ボタンを押したときの反応もない。

### 1.3 提案: 「光が先、物が後」

アートワークが光源、という既存のコンセプトをモーションにも適用する。

- **Now Playing を開くとき**
  - まずドックの面そのものが上に伸びる（translate と height。ワイプではなく面が持ち上がる）。
  - 追いかけてジャケットが着地する（ポータルなどで最前面に描画して切り取られないようにする）。
  - 最後に波形のバーが**左から右へ順に立ち上がる**。一続きの演出を 1 回だけ見せる。
  - 閉じるときは同じ動きを約 7 割の時間で逆再生する（入るより出る方を速く）。
- **曲送り**
  - `popLayout` にして、前後の曲が同時にすれ違うようにする。
  - ジャケット・タイトル・アーティスト・背景の光を 1 本のタイムラインにまとめる。方向（次は左、前は右）はそのまま残す。
- **歌詞をこのアプリの見せ場にする**
  - 現在行は色の変化だけでなく、行の長さ（次の行が始まるまでの時間）に合わせて、左から右へ文字が明るくなっていく表現にする。
  - `background-clip:text` のグラデーション位置を、補間した時間で動かす。
  - 波形と同じ「横に流れる時間（Strip）」の考え方を歌詞にも使えて、ほかのプレイヤーと差がつく。
- **操作への反応**
  - 押したときの反応（scale 0.96 で 80ms）。
  - 再生／一時停止アイコンの切り替えアニメーション。
  - サイドバーの選択中表示のスライド（`layoutId`）。
  - 自動で動くものは今のままにして、ユーザーの操作に反応する部分だけを丁寧にする。

## 2. 全体のビジュアル

- **色**
  - shadcn の無彩色そのままで、どのアプリかわからない。
  - 例外を 1 箇所だけ作り、**再生済みの波形と現在の歌詞行だけアートワークの色で光らせる**。光源というコンセプトが、操作できる部分まで届く。
- **波形**
  - 再生済みは白、未再生は明るいグレー（約 70%）で、差がほとんどない。
  - 未再生は約 35% まで落とす。
- **文字の強弱**
  - ほぼ全部 14px の medium で、平坦。
  - Now Playing では 352px のジャケットの下に `text-lg` の曲名が小さく乗っていて、釣り合っていない。
  - 曲名は `text-4xl` 程度まで大きくする。Now Playing だけは思い切って大きな文字を使ってよい。
- **再生ボタン**
  - DESIGN.md では「白い丸」だが、実装は角丸の四角。
  - 停止中は灰色の四角になり、濁って見える。

## 3. 画面ごとの指摘

### タイトルバー

- アプリ名が常に表示されているが、情報になっていない。
- 現在地のパンくず表示に使うか、何も置かない。

### ライブラリのヘッダー

- `2 albums` がタイトルから離れた行にある。Sort もラベル付きのフォームのような見た目。
- 「タイトル＋件数」を 1 本のベースラインに揃え、検索と並び替えを 1 行にまとめる。

### トラック一覧

- マウスでクリックした後、行全体が白い太枠で囲まれる。`focus-within:ring` がクリックによるフォーカスにも反応しているため。`has-[:focus-visible]` に変える（`track-table.tsx:174`）。
- 行の高さ約 52px は、技術寄りの表としては緩すぎる。40px 程度が適切。

### アルバム詳細

- DESIGN.md で禁止している大文字の `ALBUM` 見出しや、中黒（`·`）区切りが残っている（`media-details-header.tsx`、`album-details-page.tsx`、`artist-tile.tsx`）。
- 曲の長さを表すバー（Strip）が、灰色の太いバーのせいで読み込み中のバーに見える。
- 「Tracks」という見出しは重複している。
- Quality 列は `96.0 kHz • 24-bit` 表記で、DESIGN.md の `FLAC 24/96` 表記と揃っていない。

### Now Playing

- 歌詞がないとき、右の広い空間に 1 文だけが浮いている。歌詞がない場合は、ジャケットと曲情報を大きく中央に置くレイアウトに切り替える。
- 「⌄ Close」のテキストボタンが取って付けたように見える。ジャケットがあった位置に、⌄ のアイコンだけを置く方が自然。

### キュー

- 背景に blur と暗幕が掛かるため、「開いたままライブラリを見て回れる」という意図と矛盾している。
- サムネイルがなく、並べ替えも上下ボタンだけ。

### 設定

- `Include  in library` にスペースが 2 つ入っている。
- Remove ボタンが常に赤いボタンとして表示されていて重い。控えめな ghost ボタンで十分。
- ページ説明文「Manage the folders…」が、再生関連の設定が増えた今の内容と合っていない。

### ステータスバー

- 待機中は「System default」の 1 つだけのために 28px の帯を使っている。
- ドックの右側に統合するか、再生中だけ表示する。

## 5. テスト方針

`dock.e2e.ts` は、アニメーションが終わるのを `waitForTimeout(500)` で待ってから高さや位置を測っている。開閉や曲送りを作り直すと、この待ち方は壊れやすくなる。

1. **e2e は既定でモーションを切る。**
   - `playwright.config.ts` の `use` に `reducedMotion: "reduce"` を足す。トークンは reduced-motion のとき 100ms のクロスフェードに落ちるので、アプリ側の変更は要らない。
   - `waitForTimeout` は消せる。
   - 「開閉してもドックの高さと再生ボタンの位置が変わらない」といった形のテストが、待ち時間なしで安定する。
2. **動きそのもののテストは別ファイルに分ける。**
   - `motion.e2e.ts` で reduced-motion を切り、実際のタイミングで確認する。
   - 見るのは不変条件だけ。開閉の途中でもドックの下端が動かない、曲送りの途中で空白のフレームがない、など。
   - 軌跡のスクリーンショット比較はしない。
3. **補間ロジックは純関数にして vitest で書く。**
   - 再生位置の補間と、歌詞の行内進捗が対象。
   - `use-lyrics-sync` と同じ作りにする。ブラウザなしで、「位置が届く→進む→シークで跳ぶ」を検証できる。
4. **既存の 2 つのテストは意味が変わる。**
   - `tokens.test.ts` の「spring は全部 `bounce: 0`」は、線形の補間が入るなら条件を直す。
   - `light-model.test.ts` は、アートワーク色を歌詞や波形に使うなら、コントラストの検証を足す。

テスト設定の変更（1）と補間ロジックの純関数化（3）は、アニメーション修正の前に入れると、その後の作業が楽になる。

## 6. CSS 構造

`styles.css` は 181 行で、トークン、`@theme`、base が 1 ファイルにまとまっている。分割する規模ではない。直す点は 3 つ。

1. **モーションの値が 2 か所に分かれている。**
   - JS 側は `tokens.ts` の秒数と spring、CSS 側は `--default-transition-duration: 100ms` と `duration-160`。
   - `@theme` に `--duration-*` と `--ease-*` を置き、CSS はそれを参照する。
   - JS 側は `getComputedStyle` でその変数を読むか、変数を生成元にして `tokens.ts` を作る。定義は 1 か所にする。
2. **オーバーレイの動きが 2 種類ある。**
   - Sheet は `data-starting-style` で、Tooltip・Select・Dialog は `tw-animate-css` の `animate-in`。
   - アプリ固有の動きにするなら、`data-starting-style` 方式に寄せる。これで `tw-animate-css` の依存を外せる。
3. **アートワーク色を使うなら CSS 変数にする。**
   - `--artwork-accent` をシェルに 1 つ置き、波形と歌詞行はそれを参照する。
   - JS のインライン style をあちこちに散らすより、変更箇所が 1 つで済む。

ついでに直したい点: reduced-motion の CSS は `transition-duration: 0s` で、JS 側の「100ms のクロスフェード」と食い違っている。片方に揃える。

## 7. UI コード構造

大枠は問題ない。FSD の層分け（app / pages / widgets / features / entities / shared）は守られていて、ほとんどのファイルが 300 行以下。ここで見たのは UI 層だけで、`playback-session.ts`（zustand）やクエリ層の中身は見ていない。直すのは再生まわり（dock と Now Playing）だけ。

### 直したい点

1. **dock と Now Playing が widget をまたいで絡んでいる。**
   - `now-playing-content.tsx` が `widgets/playback-region` から `PlaybackWaveformBand` を import していて、widget 同士の横断参照になっている。
   - `layoutId`（`now-playing-sleeve`、`now-playing-title`、`now-playing-waveform`）も、`dock-identity.tsx`、`playback-waveform-band.tsx`、`now-playing-content.tsx` に文字列で散らばっている。
   - 一続きの演出を 4 ファイルに分けて書いているので、§1.1 のジャケットの切り取りやドックの潰れを直しにくい。
   - 対策: 開閉と共有要素の演出を持つ場所を 1 つ決める。`layoutId` の名前は定数にして、そこから export する。波形は `shared` か `features` に移して、横断参照をなくす。
2. **`nowPlayingOpen` を props で 4 段運んでいる。**
   - `PlaybackRegion` → `PlaybackDock` → `DockIdentity` → `Sleeve` と渡されている。
   - `useNowPlaying()` は既にあり、`Sleeve` の中で直接読める。
   - `trackChangeTransition` も同じ経路で運ばれている。
3. **曲送りの方向を `useRef` に持たせて、render 中に読んでいる**（`directionRef.current`）。
   - 再レンダーのタイミングに依存していて、壊れやすい作りになっている。
   - 「次へ／前へ」を押した瞬間の方向は、`playback-session` 側に `lastNavigation` として持たせるのが素直。

4. **`waveform-seek.tsx`（265 行）が 1 つのコンポーネントに詰まっている。**
   - ポインタ操作、描画、アニメーション、ホバー表示が同居している。
   - 分割案: `usePointerSeek`（ポインタ操作とドラッグ状態）、`useInterpolatedPosition`（再生位置の補間）、`WaveformBars`（描画のみ）、`WaveformSeek`（組み立て）。
   - 補間を rAF に替える §1.1-4 は、この分割の上で行う。

### ファイル配置の目標

変更量を問わないなら、再生まわりは次の形にする。

- `shared/ui/waveform/`: `WaveformSeek`、`WaveformBars`、上記 2 つの hook（dock と Now Playing の両方が使う部品）
- `features/now-playing-transition/`: 開閉と共有要素の演出。`layoutId` の定数、開閉状態、曲送りの方向、演出用のトークンを持つ
- `widgets/playback-region/`: dock だけ。Now Playing を知らない
- `widgets/now-playing/`: Now Playing だけ。dock を知らない
- `entities/playback/`: `lastNavigation`（次へ／前へ）を追加

dock と Now Playing は `features/now-playing-transition` だけを介してつながる。widget 同士の import はなくなる。

これは §4 の着手順 2・3 と同時に行う。別々にやると同じファイルを二度触ることになる。
