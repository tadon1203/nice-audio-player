# Domain Docs

How the engineering skills use this repo's domain documentation.

This is a single-context repo. Before you explore, read:

- `CONTEXT.md` (repo root): the glossary.
- `docs/adr/`: the ADRs for the area you will work in.

If one is missing, continue. The `/domain-modeling` skill (through `/grill-with-docs`) creates them when needed.

- Use the `CONTEXT.md` term for a domain concept in issue titles, refactor proposals, and test names. Do not use a synonym.
- If the glossary has no term, change the wording or note the gap for `/domain-modeling`.
- If your output contradicts an ADR, say so. Do not override it silently.
